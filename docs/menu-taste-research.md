# 로컬 주문 조건 + 외부 공식 맛 근거

가격·카테고리·옵션·판매 여부·온도는 공통 파일과 현재 PostgreSQL 조회가 기준이다. 맛은 공식 사이트에서 수집한 기본 메뉴 설명을 사용한다. 외부 가격으로 로컬 가격을 덮어쓰지 않는다. 맛 CSV·가중치 행렬은 사용하지 않는다.

## 수집 결과

2026-11-10 메가MGC커피 공식 사이트의 공개 메뉴 페이지 12개를 조회했다. 현재 45종의 온도별 설명 71건을 모두 일치시켰다.

매핑은 `common/menu_image_sources.json`의 공식 메뉴명·HOT/COLD·원본 이미지 URL 세 조건을 현재 공식 페이지와 비교한다. 메뉴명만 비슷하다는 이유로 설명을 복제하지 않는다. 기존 레몬티의 레몬차 연결도 기존 공통 이미지 매핑에 근거하며 감사 파일에 별도로 남는다.

- `common/menu_evidence.json`: 실제 설명, 출처 URL, 확인일. 추천에 바로 사용하는 캐시.
- `common/menu_research_audit.json`: 메뉴 ID·온도·공식명·이미지 URL·원본 페이지 SHA-256과 일치/미일치 목록.
- `backend/app/services/menu_research.py`: 공식 자료 갱신 명령. OpenAI 호출은 하지 않는다.
- `backend/app/services/taste_evidence.py`: 공식 설명의 정성 단서를 확인하는 검증. 숫자 맛 점수나 순위표가 아니다.

공식 페이지 예: https://www.mega-mgccoffee.com/menu/menu.php?page=6

## 추천 흐름

1. 현재 DB의 가격·판매·종류·온도·옵션을 읽는다.
2. 확인된 공식 설명으로 맛·향·과일 조건의 근거가 있는지 확인한다. 지원하지 않는 선택지는 `eligible_for_request=false`로 표시하고 출력 스키마의 선택 가능 ID에서도 제외한다.
3. LLM이 전사 원문·음성 해석 예시·현재 메뉴·공식 설명을 보고 적합한 후보와 순서를 결정한다. 맛·향 조건 응답에는 `description` 근거 필드를 반드시 포함해야 한다.
4. 서버가 가격·종류·맛 근거·선택 온도·중복·추천 개수를 확인한다. 요청 개수가 없으면 최대 6개, 5~6개는 화면에 4개 미리보기와 전체보기를 제공한다.

음성 요청 때마다 외부 웹 검색을 반복하지 않는다. 저장된 공식 설명을 사용하므로 외부 사이트 응답 지연을 추천 요청에 추가하지 않는다. LLM 유료 API 호출은 기존처럼 별도로 발생한다.

## 이번 오류 방지 예

공식 아메리카노 설명은 에스프레소와 물을 설명하며 달콤함을 뒷받침하는 단서가 없다. 꿀아메리카노 설명에는 ‘달콤한 사양벌꿀’이 있다.

현재 로컬 가격에서 ‘삼천 원 이하 달달한 음료’ 요청의 설명·가격 검증을 통과한 후보는 꿀아메리카노, 바닐라 아메리카노, 헤이즐넛 아메리카노, 복숭아 아이스티, 제로 복숭아 아이스티다. 일반 아메리카노는 출력 가능 ID에서 제외된다. 이 목록은 서버의 가능 후보이며 실제 LLM이 반환한 실험 결과가 아니다.

과일 스무디 요청에서는 공식 설명에 과일 근거가 있는 딸기·망고·블루베리 스무디가 통과하고 플레인요거트스무디는 제외된다. 요청한 두 개 제한은 그대로 적용한다.

제로슈가가 단맛 없음이라는 뜻은 아니다. 제로 복숭아 아이스티 공식 설명의 대체당 표기도 참고하며, 당류 수치로 체감 단맛을 임의 계산하지 않는다.

## 한계와 검증

단맛·상큼함·과일 단서는 공식 설명에 실제 표현이 있는지 보수적으로 확인한다. 이는 체감 강도의 실측이 아니며, 공식 설명이 모호한 메뉴가 후보에서 누락될 수 있다. 완전한 취향 이해나 추천 정확도를 보장하지 않는다. 우유·카페인·알레르기 전용 필드는 이번 수집으로 추정해 채우지 않았다.

수집 자료 자체의 매핑·출처 검증과 일반 아메리카노 제외·꿀아메리카노 허용·과일 스무디·가격 기준 등의 회귀 테스트를 실행했다. 실제 유료 LLM의 정확도 전후 측정은 API 키가 없는 환경이라 수행하지 않았다.

## 자료 갱신

프로젝트 루트 또는 백엔드 Python 모듈 실행 환경에서 다음 명령을 실행한다. Docker 백엔드에는 COMMON_DIR=/common이 설정돼 있다.

```powershell
docker compose exec backend python -m app.services.menu_research --output /tmp/menu-evidence-new.json --audit /tmp/menu-research-new.json
```

결과의 `unmatched`가 비어 있는지 확인하고 출처를 검토한 뒤 복사한다.

```powershell
docker compose cp backend:/tmp/menu-evidence-new.json .\common\menu_evidence.json
```

```powershell
docker compose cp backend:/tmp/menu-research-new.json .\common\menu_research_audit.json
```

갱신 명령은 기존 출력 파일을 덮어쓰지 않는다. 재실행에는 새 파일명을 사용한다. 이미지·레시피가 바뀌어 일치하지 않는 메뉴는 미확인으로 남기며, 운영 파일로 반영하기 전에 검토한다. 사이트의 페이지 수나 HTML 구조가 바뀌면 수집기도 확인해야 한다.

### 맛 제외 표현

원하는 맛(`flavors`)과 제외할 맛(`excluded_flavors`)을 구분한다.
“레몬 말고 딸기”, “레몬이랑 망고는 빼고 딸기”는 딸기 후보만 남기고 레몬·망고가 공식 설명에 포함된 혼합 메뉴도 제외한다.
“레몬은 빼지 말고”는 제외 조건으로 해석하지 않는다. 현재 지원하는 맛 토큰은 딸기·레몬·망고·초콜릿·과일이다.
공식 설명의 표현을 기준으로 한 추천 필터이며, 전체 성분이나 알레르기 안전성을 보증하지 않는다.

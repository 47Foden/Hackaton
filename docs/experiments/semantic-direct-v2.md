# 의미 해석 방식 v2: 실제 오류를 바탕으로 한 무료 보완

브랜치: experiment/taejun-llm-semantic-direct. 이전 공유 브랜치 및 main은 유지한다. 여기서 v1/v2는 새 의미 해석 실험 모듈의 버전이며 과거 추천 실험 V1~V3와 구분한다.

## 실제로 확인된 문제

첫 유료 8회 비교에서 새 의미 해석 방식은 복합 제외를 올바르게 해석해 딸기 후보를 선택했다. 그러나 일반 딸기 요청은 메뉴 ID 중복, 이중 부정은 추천과 미해결 조건을 동시에 반환해 사용자에게 전달되지 못했다. 소수 표본이므로 전체 정확도나 속도 개선은 입증하지 않았다.

## 보완

1. 응답의 decision을 추천/자료 부족 중 하나의 객체로 반환하도록 분리했다. 추천 객체는 후보가 1~6개이고 미해결/자료 부족 목록이 비어야 한다. 자료 부족 객체는 후보가 없고 필요한 자료가 하나 이상 있어야 한다. nested anyOf를 사용하며 루트는 object다. 무료 스키마/검증 시험을 했지만 공급자의 실제 새 스키마 수락과 생성 결과는 아직 미측정이다.
2. 허용·비거부 표현은 강제 선호도 미확인 위험 조건도 아니라는 지침을 명확히 했다. 일반적인 '음료'를 논커피 대분류로 제한하지 않도록 했다. 원문을 Python으로 재해석하거나 사전 후보 필터를 도입하지 않았다. 이 프롬프트 효과는 실제 모델 재시험이 필요하다.
3. 동일 메뉴·온도·옵션 중복은 모든 사실 검증을 통과한 뒤 첫 등장 순서로 하나만 전달한다. raw_contract_issues 및 normalizations에 위반과 제거 인덱스를 남긴다. 다른 온도/옵션의 중복은 충돌로 거부한다. 잘못된 옵션이나 unknown 근거가 있는 중복을 그냥 버려서 안전 검사를 우회하지 않는다.
4. 유료 비교 기록에는 원본 응답 계약 통과 여부와 정규화 후 전달 가능 여부를 구분하도록 했다. 정규화된 성공을 모델 생성 품질 개선으로 계산하지 않는다.

## 같은 실제 응답 재생

`semantic_v1_live_cases.json`에 실제 새 방식 v1 응답 4개를 허용 목록으로 추출했다. API 키·전체 공급자 오류 본문은 없고 원본 결과 SHA-256을 기록했다. `semantic_v1_snapshot.py.txt`는 해당 유료 실험 소스 해시와 일치하는 고정 코드다. 운영 경로에서 사용하지 않는다.

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path + ';' + (Resolve-Path backend/tests).Path
python -X utf8 -B -m app.evaluation.replay_semantic_v2 --output-dir PATH_TO_REPLAY
```

재생 시 v1/v2의 바깥 형식만 어댑트했다. 해석·후보·미해결 문구는 수정하지 않았다. 기준 코드·메뉴·설명 해시 일치 및 당시 v1 오류 코드 재현을 확인한다.

| 실제 v1 응답 | v1 검증 | v2 검증/처리 |
|---|---|---|
| 단순 제외 | 5개 전달 | 같은 순서로 5개 전달 |
| 복합 제외 | 5개 전달 | 같은 순서로 5개 전달 |
| 이중 부정의 추천+미해결 모순 | 거부 | 여전히 거부. 내용을 지우거나 성공으로 바꾸지 않음 |
| 일반 딸기의 중복 목록 | 전체 거부 | 동일 중복을 사실 검증 후 제거하고 5개 전달, 원본 위반은 기록 |

이것은 과거 고정 응답의 사후 처리 시험이다. '실제 모델 정확도가 2/4에서 3/4로 상승했다'는 결과가 아니다. 새 프롬프트에서 생성한 유료 응답은 아직 없다.

## 안전 검증과 한계

무료 검증은 새 의미 해석/비교/유료 실행기/실제 오류 회귀 34개와 기존 관련 회귀 42개, 합계 76개가 통과했다. 직접 실행용 run-semantic-free.cmd의 테스트·요청 8개 생성·실제 응답 4개 재생도 완료했다. 모델/API 추가 호출은 0회다.

실제 ID·판매 여부·온도·옵션·합산 가격·확인된 성분/카페인·제외 설명 충돌 검증을 유지한다. 추천+미해결 및 미확인 알레르기 조건은 거부하고, 자료 부족 상태를 추천으로 바꾸지 않는다. LLM이 원문 조건을 누락하거나 잘못 해석하면 서버가 모두 알아낼 수는 없다. 설명 문자열 검사는 여전히 제한적이며 원재료 부재를 보장하지 않는다.

다음 유료 평가는 이전 평가 발화 외에 같은 뜻의 새 말투를 포함해야 한다. 원본 후보 생성의 유일성/조건 해석, 정규화 후 전달 가능 여부, 시간·토큰·캐시 비용을 분리한다. 기존 8회 결과는 보존하고 입력/소스 해시가 달라진 결과를 섞지 않는다. 추가 유료 호출은 별도 범위·비용 확인 후 진행한다.

변경은 새 의미 해석 모듈·실험 실행기·테스트·문서에 한정한다. 기존 웹/음성 기본 경로·DB·공용 Docker 설정은 바꾸지 않았다. 추가 API 호출·실제 키 파일 접근·commit·push·merge는 하지 않았다.

# 추천 구조 변경 제안
### 문장의 의미 판단은 LLM에, 확인 가능한 사실 검증은 서버에

**변경 이유**
현재 main도 LLM이 원문을 읽지만, 먼저 Python이 문장을 해석해 추천 가능한 메뉴를 제한합니다. 이 사전 해석이 틀리면 **LLM이 맥락을 이해해도 적합한 메뉴를 선택할 수 없습니다.**

> **재현 사례:** “레몬이랑 망고는 빼고 딸기”
> 의도: 레몬·망고 제외 + 딸기 선호
> 현재 main: 세 맛을 모두 선호로 읽음 → 허용 후보 0개

| 역할 | 현재 main | 제안 구조 |
|---|---|---|
| 원문 의미 판단 | Python 규칙 + LLM | **LLM이 문맥을 해석** |
| 메뉴 선택 | Python이 허용한 후보에서 LLM 선택 | **실제 메뉴 자료에서 LLM이 직접 선택** |
| 서버 검증 | 의미 해석·사전 제한·응답 검증 | **ID·판매 여부·가격·온도·옵션·근거 등 사실 검증** |

**제안 흐름:** 원문 + 실제 메뉴 자료 → LLM의 해석·후보 선택 → 서버 검증

**기대하는 개선**
여러 대상을 묶는 제외, 부정, 말 바꾸기 등 자유로운 표현을 사전 규칙이 잘못 확정해 후보를 막는 문제를 줄일 수 있습니다. 해석과 선택을 같은 응답에서 받아 **추천 API 호출은 1회로 유지**하며, 숫자 맛 점수로 다시 순위를 계산하지 않습니다.

**확인한 근거와 한계**

- 현재 main `f6bbfcb`에서 위 후보 제한을 무료로 재현했습니다.
- 실제 main 대 v2를 새 말투 4개로 각각 1회씩 비교했습니다. **main에서 막힌 단순·복합 제외 두 발화는 v2가 모두 딸기 후보 5개를 전달했습니다.**
- 이번 표본의 전달 가능 응답은 main 2/4, v2 4/4였습니다. 다만 v2도 이중 부정에서 레몬을 잘못 제외했고, 일반 딸기 요청의 중복은 서버 정규화로 처리했습니다. **4/4 전달은 정확도 100%가 아닙니다.**
- v2의 기록된 해석은 사전 기준과 2/4 일치했습니다. 평균 API 시간은 main 약 2.48초, v2 약 3.66초로 이번에는 v2가 더 걸렸습니다. 8회 비용은 합계 약 $0.195였습니다.
- 무료 회귀 테스트 76개 통과와 별도로 실제 응답을 검토했습니다. 각각 한 번의 작은 표본이므로 전체 정확도·반복 일관성·속도 향상을 주장하지 않습니다.

**팀 검토 요청**
사전 규칙 병목을 줄이는 방향은 실제 사례에서 효과가 확인됐으므로 별도 실험을 이어가고자 합니다. main 교체 전에는 남은 해석 오류·조건 누락과 다른 조건 유형/반복 실행도 보완·검증해야 합니다. 현재 main과 웹/음성 기본 경로는 유지했고, 이번 결과 검토 과정에서 추가 유료 호출은 하지 않았습니다.

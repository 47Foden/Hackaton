# 첫 실제 LLM 직접 추천 비교 결과

**현재 실험으로 기존 방식보다 개선됐다고 결론 내릴 수 없다. 운영 기본값은 기존 방식을 유지한다.**

## 실행 조건

- 실행일: 2026-11-09 (한국 시간). 사용자가 본인 CMD에서 키를 로드해 실행했다.
- 모델: gpt-5.4-mini-2026-03-17 / reasoning none / 출력 상한 1800토큰 / 자동 재시도 없음.
- 실제 로컬 /api/menus의 메뉴 11개와 판매 여부·가격·온도 스냅샷을 두 경로가 공유했다. 합성 판매 여부를 사용하지 않았다.
- LLM에는 별도 확인한 공식 설명을 추가했으며 숫자 맛 점수는 주지 않았다. 기존 경로는 원래 CSV/규칙을 그대로 사용했다.
- 사람이 쓴 조건 주석은 LLM에 전송하지 않고 서버 검증에만 사용했다.
- 최초 연결 확인은 API 응답 수신에 성공했으나 가격 위반으로 거부됐다. 원래 응답과 스냅샷을 보존해 연결 확인을 다시 호출하지 않고 나머지 다섯 발화만 실행했다.
- 비용 기록은 총 6회(연결 확인 1회 + 비교 5회)이며 각 발화는 한 번씩만 실행했다.

## 발화별 관찰

| 발화 | 기존 경로 | LLM 경로 | 검토 메모 |
|---|---|---|---|
| 커피 제외·삼천 원 | 입력 해석 오류 | 가격 위반으로 거부 | 3300원 메뉴를 예산 안이라고 설명. HOT/COLD로 같은 ID도 중복 반환. |
| 깔끔한 음료 | 입력 해석 오류 | 중복 ID로 거부 | 선택은 산미/탄산 설명을 활용했으나 레몬차를 HOT/COLD로 중복 반환. INVALID_MENU_ID 코드는 이 경우 존재하지 않는 ID가 아니라 중복을 뜻함. |
| 달지만 끈적하지 않게 | 후보 4개 반환 | 서버 검증 통과 | 통과는 적합성 보장이 아님. 레몬차의 단맛을 공식 설명에 있다고 했으나 제공된 설명은 산미·향만 언급. 끈적함 자료 부재를 언급했지만 질문하지 않음. |
| 우유 제외·신맛 허용 | 입력 해석 오류 | 제외 조건 미확인으로 거부 | 우유 포함 확인 없음과 우유 미포함을 구별하지 못한 추천. 근거 부족 시 질문/자료 부족 응답이 필요. |
| 밤·잠 깨는 음료 제외 | 커피 3종 반환 | 보수적 제외 검증으로 거부 | 공식 표기 0mg 메뉴를 고른 방향은 타당할 수 있으나 수면 영향 표현은 단정할 수 없음. 현재 unverified_exclusions는 후보 전체를 거부하므로 검증기의 자료 활용 한계도 포함. |

위 메모는 코드와 제공 자료를 대조한 개발 검토이며 독립된 사람 평가나 블라인드 사용자 평가가 아니다. JSON의 human_review 점수는 미평가 null을 유지한다.

## 측정값

- 다섯 발화 중 LLM 응답의 서버 검증 통과: 1/5. 이를 추천 정확도 20%로 해석하면 안 된다.
- 기존 경로의 정상 함수 반환: 2/5. 원래 함수에 LLM 검증기를 적용하지 않았으므로 이를 같은 기준의 조건 준수율로 비교하면 안 된다.
- 다섯 발화 평균 지연: 기존 1.055 ms / LLM 2704.287 ms. 단일 로컬 실행 표본이며 모델 호출과 응답 검증 시간을 포함한다.
- 전체 6회 입력 26086토큰 / 출력 1180토큰 / 합계 27266토큰.
- 전체 비용 추정: USD 0.02487450. 입력/캐시 입력/출력 백만 토큰당 USD 0.75/0.075/4.50을 사용했다. 계정 청구서·잔액 조회는 하지 않았다.
- 기존 요청별 LLM 비용은 0이며 CSV를 만들었던 사전 비용과 Whisper 비용은 제외했다.
- 반복 일관성, p95 지연, 통계적 유의성은 측정하지 않았다.

## 최초 연결 확인의 실패도 보존

3000원 이하 차가운 음료 요청에 LLM은 3300원 레몬차·유자차를 포함했고 서버가 거부했다. 기존 경로는 HOT만 가능한 에스프레소를 포함했다. 기존 규칙이 차가운이라는 표현을 온도로 인식하지 못하는 한계가 있다. 이 실패는 비교에서 숨기거나 성공으로 교체하지 않았다.

## 후속 개선 제안 (아직 적용하지 않음)

1. 후보의 단위를 메뉴 ID 하나로 명시하고 같은 ID의 온도 중복을 금지한다. 중복 오류와 존재하지 않는 ID 오류를 구별하면 분석하기 쉽다.
2. 예산 산술·판매 여부·가능한 온도는 계속 서버에서 검증한다. 후보를 조용히 보정하거나 기존 맛 점수로 재정렬하지 않는다.
3. 우유 없음과 정보 없음, 카페인 표기 0mg와 수면 영향 보장을 명확히 구분하고 질문/자료 부족 응답을 검증한다.
4. 출처가 있는 정형 메뉴 사실을 온도별 제외 검증에 연결하는 별도 실험을 설계한다. 현재 blanket exclusion이 너무 보수적인 경우도 측정한다.
5. 더 다양한 발화와 반복 실행, 독립 평가로 개선을 확인한 후에만 웹·음성 연결을 검토한다.

# 기존 직접 추천 vs LLM 의미 해석: 유료 비교 준비

대상은 기존 `769d2d9` 기반 `llm_direct`와 별도 `llm_semantic_direct`다. 같은 `gpt-5.4-mini-2026-03-17`로 단순 제외·복합 제외·이중 부정·일반 요청 4개를 각 방식 1회씩 비교한다. 요청/프롬프트/자료의 SHA-256과 코드 해시를 기록한다. 해석과 후보 선택은 새 방식에서도 한 요청/응답 안에서 이루어진다.

## 유료 호출 전 무료 확인

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path + ';' + (Resolve-Path backend/tests).Path
python -X utf8 -B -m unittest test_semantic_paid_study -q
python -X utf8 -B -m app.evaluation.semantic_paid_study --mode plan --output-dir PATH_TO_PLAN
```

기본 모드는 plan이다. plan/mock은 실제 키 파일을 읽거나 공급자를 호출하지 않는다. free 비교 CLI와 기존 서비스 경로는 변경하지 않았다.

## 소유자가 직접 실행할 때만

```powershell
python -X utf8 -B -m app.evaluation.semantic_paid_study --mode live --allow-paid-api --env-file PATH_TO_BACKEND_ENV --output-dir PATH_TO_STUDY
```

실행기에는 --mode live, --allow-paid-api, 대화형 터미널, --env-file 및 RUN8 확인이 모두 필요하다. 이후에만 지정 .env의 OPENAI_API_KEY를 읽는다. 키 값은 프롬프트·명령 인수·결과에 넣지 않는다. 실제 API/키 파일을 사용하는 실행은 키 소유자 PC에서만 한다.

요금 기준은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini), 2026-11-12 확인: 100만 토큰당 입력 $0.75, 캐시 입력 $0.075, 출력 $4.50. 지난 호출당 실측 약 $0.025를 기준으로 8회 약 $0.20를 참고할 수 있지만 새 방식의 실제 비용은 미측정이다. 입력 바이트를 넉넉하게 잡은 계획액은 별도로 표시하며 예상 청구액이나 강제 결제 상한이 아니다. 실제 usage로 비용을 계산한다.

비교 횟수는 기존 4회 + 신규 4회로 유지한다. 두 방식 모두 실험 요청의 최대 출력량만 8192에서 2048토큰으로 동일하게 낮췄다. 서비스 모듈의 기본값이나 메뉴 자료는 변경하지 않았다. 입력 비용이 대부분이므로 출력 상한 감소가 실제 비용의 큰 절감을 보장하지 않는다. 출력 제한에 걸리면 미완료 응답으로 기록되며 자동 추가 호출은 하지 않는다. 요청 해시/계획 지문이 바뀌므로 이전 설정으로 시작한 결과와 혼합하지 않는다.

## 중단/재개 및 횟수 제한

- 동일 결과 폴더 전체에서 최대 8회 시도. 자동 재시도는 없다. 이전처럼 별도 연결 확인 호출도 하지 않는다.
- 요청 시작 사이 최소 30초 간격. 실험용 대기이며 API 응답시간에는 포함하지 않는다. 계정별 한도나 다른 사용자의 요청이 있어 429를 막는다는 보장은 없다.
- 429 등 공급자 오류는 안전한 오류 코드/type와 숫자 Retry-After만 기록하고 중단한다. 오류 본문·키·계정 정보는 저장하지 않는다.
- 완료한 항목, 이미 실패한 항목, 결과를 받았는지 불확실한 항목을 자동으로 다시 호출하지 않는다. 같은 결과 폴더로 실행하면 아직 시작하지 않은 항목만 남은 8회 상한 안에서 실행한다. 실패한 호출을 다시 시도하려면 별도 승인/실험이 필요하다.
- 결과는 호출 전에 started 상태로 기록한다. 전원 종료 등으로 결과를 잃으면 다음 실행에서 과금 불명 항목으로 보존하고 건너뛴다.
- 동시에 두 번 켜지 못하도록 study.lock을 사용한다. 강제 종료로 lock이 남으면 실제 실행 중인 창이 없는지 확인하고 lock 정리를 요청한다. 다른 실행이 진행 중인지 확인하지 않고 삭제하지 않는다.
- 요청/코드/자료가 바뀌면 기존 결과와 섞지 않고 중단한다.

## 결과 해석

results.json과 report.ko.md에 모델 원본 후보, 서버 검증 결과, 제한된 후보 조건 검사, 해석 기준 일치, API 시간, 토큰 및 비용을 분리한다. 기존 방식의 해석 일치는 Python 조건을, 새 방식은 LLM의 반환 조건을 비교한다. 기존 모델의 내부 사고 과정을 측정한 것이 아니다.

사람이 작성한 평가 기준은 모델 프롬프트에 제공하지 않는다. 후보 검사는 해당 발화의 딸기/레몬/망고 맛 단서 및 서버 검증 통과 여부로 제한된다. 모델이 조건을 누락하는 문제·근거의 의미상 정확성·주관적 추천 적합성은 사람이 검토해야 한다.

같은 모델을 사용하지만 프롬프트·응답 스키마·조건 힌트와 허용 후보 범위는 다르다. 모델 학습이나 모델 자체의 우월성 비교가 아닌 추천 파이프라인 실험이다. 각 사례 1회라 전체 정확도·반복 일관성·속도 개선을 입증하지 못한다. 메뉴 판매 상태는 시험용으로 모두 True이며 실제 DB/STT/서비스 배포 실험은 아니다.

추가 파일은 `backend/app/evaluation/semantic_paid_study.py` 및 `backend/tests/test_semantic_paid_study.py`다. 실제 유료 호출은 준비 과정에서 하지 않았다.

# v3 초안: 응답 계약을 줄인 LLM 직접 추천

v2의 실제 실패를 반영한 별도 실험이다. v2 결과를 고치거나 성공으로 다시 집계하지 않는다. 웹·Whisper·기존 추천은 바꾸지 않았다. 유료 호출, commit, push는 이번 보완에서 하지 않았다.

## 변경 목적과 범위

| v2에서 관찰한 문제 | v3 변경 | 확인할 수 있는 범위 |
|---|---|---|
| 긴 태그 ID 복사 오류 | 태그 출력·감각 해석표 전송 제거 | 해당 형식 오류의 발생 경로 제거. 취향 판단 개선은 아직 미측정 |
| fit=milk/caffeine 의미 혼동 | fit 필드 제거 | 인위적인 fit 분류 때문에 거부하지 않음. 실제 우유·카페인 조건은 계속 검증 |
| 긴 근거 ID 복사 | basis_fields에 description 등 짧은 필드명 지정 | 서버가 선택한 메뉴·온도의 확인된 사실에만 연결 |
| 여러 후보와 중복 처리 부담 | 후보 최대 1개 | 단일 후보 검증. 여러 대안과 순위 품질은 이번 범위에서 제외 |
| 미등록 상품을 다른 상품으로 대체 | requested_menu_name 기록, 목록에 없으면 질문 요구 | 모델이 추출한 이름 기준의 서버 검증. 이름 누락까지 보장하지 않음 |
| 미확인 취향을 임의로 충족 | unresolved_requirements 기록, 미해결이 남으면 추천 거부 | 자가 보고가 누락될 가능성은 남음 |

LLM은 전체 실제 메뉴·가격·판매 여부·온도별 확인 사실을 읽고 후보 하나 또는 질문/자료 부족을 직접 선택한다. 기존 숫자 맛 점수표, Python 맛 순위, 기존 추천으로의 분기는 사용하지 않는다. 서버는 선택 후 사실과 명시적 조건을 검사한다. 과일 이름만으로 무우유를 추정하지 않는다.

공식 설명과 재료·카페인 사실은 기존 조사본을 사용하되, 출처 URL·날짜·자료 메모는 서버 검증 문맥에 보존하고 값만 간결하게 전송한다. assistant가 작성한 감각 태그와 해석 가설은 전송하지 않는다. 원문·메뉴 데이터 속 지시를 따르지 않도록 프롬프트를 구분한다. 이것이 완전한 주입 방어를 입증하지는 않는다.

응답은 status, requested_menu_name, recommendations(최대 1), questions(최대 1), unresolved_requirements, missing_information이다. 후보는 menu_id, temperature, basis_fields만 반환한다. 서버가 원래 사실과 출처로 근거를 구성하며 자유로운 맛 설명은 생성하지 않는다. 후보를 기존 점수로 다시 정렬하거나 자동 수정·재시도하지 않는다.

## 무료 확인 방법

저장소 루트 PowerShell, Python 3.11 이상:

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path + ';' + (Resolve-Path backend/tests).Path
python -B -m unittest test_llm_direct_v3 -v
python -B -m app.experiments.check_recommendations_v3 --v1-report docs/experiments/2026-11-09-first-live/results.json --output-dir work/v3-offline-five
python -B -m app.experiments.check_recommendations_v3 --v1-report docs/experiments/2026-11-09-first-live/results.json --cases common/experiments/llm_direct/v2_accuracy_cases.json --output-dir work/v3-offline-ten
```

출력은 `results.json`과 `results.ko.md`이며 기존 출력 폴더는 덮어쓰지 않는다.

`--responses`에 ‘발화 ID → 직접 작성한 응답’ JSON을 지정하면 후보나 질문의 검증 결과를 확인할 수 있다. 모든 발화의 응답이 필요하며, 빠진 응답을 mock으로 채우지 않는다. 직접 작성한 응답의 통과를 모델 개선으로 해석하지 않는다. 지정하지 않으면 고정된 자료 부족 mock을 사용한다. 이 CLI에는 live 모드·키 읽기·네트워크 호출이 없다.

## 검증 결과와 의미

무료 코드 테스트는 기존 76개와 신규 18개, 총 94개 통과했다. 예산·온도·판매·미등록 ID·우유 미확인·0mg·잘못된 근거·질문 개수·미해결 조건·API 거부/중단 처리를 확인했다. 기존 추천과 같은 텍스트로 비교하는 5개 발화 및 v2 개발용 10개 발화의 mock 출력을 생성했다. 이 통과 건수는 추천 정확도가 아니다.

5개 발화의 입력 데이터 문자 수 합계는 v2=177521, v3=23801로 약 86.6% 줄었다. 시스템 문장과 스키마를 제외한 입력 JSON의 문자 수 비교이며, 토큰·응답시간·비용 실측이나 같은 비율의 개선을 뜻하지 않는다.

## 남은 문제와 다음 평가

- 모델이 특정 상품명이나 미해결 조건을 신고하지 않으면 놓칠 수 있다. 질문의 의미, 맛 적합성, 설명과 요구의 관련성을 기계 검증만으로 보장하지 않는다.
- 한국어 조건 해석은 v2의 제한된 표현 처리를 재사용한다. 복합 부정·인용문·새로운 표현에서 오류가 날 수 있다.
- 뒷맛·떫음 관능 평가, 독립된 정답 데이터, 질문 이후 여러 차례 대화의 상태 유지는 미구현·미확보다.
- v2의 사실 검증과 문맥 준비를 재사용하므로 현재는 근거와 기존 태그표의 정합성 검증에 의존한다. 단, 태그는 모델 입력과 출력에서 제외했다.
- 저장된 메뉴 가격·판매 상태가 현재 상태와 같다는 보장은 없다. 이번 단위 테스트의 판매 상태는 합성값이다.
- 실제 API 형식 수용, 정확도, 속도, 비용, 반복 일관성은 이번에 측정하지 않았다.

다음 실제 실험은 예산/온도, 설명에 명시된 맛, 우유 미확인, 뒷맛 미확인, 미등록 상품을 같은 조건으로 비교한다. 올바른 추천과 적절한 질문/자료 부족을 나누고, 원래 응답의 실패와 서버 거부를 보존한다. v2의 10개 발화는 회귀용이며 최종 판단은 사용하지 않은 표현과 독립된 사람 평가로도 확인한다. 추가 API 실행은 키 소유자의 별도 지시 후 진행한다.

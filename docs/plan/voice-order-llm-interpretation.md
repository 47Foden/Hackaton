# 음성 주문 메뉴 매칭 및 LLM 해석 구현 계획

## 목표

`주문하기`로 녹음한 발화에서 카탈로그 메뉴명을 찾으면 주변 표현이 등록된 옵션인지와 관계없이 메뉴 후보로 잡는다. STT 직후 주문 전용 LLM으로 발화를 해석해 온도, 추가 옵션, 매장·포장 선택에 반영한다. 예를 들어 “뜨듯한 아메리카노”는 아메리카노를 선택하고 온도를 `HOT`으로 설정한다.

현재 코드의 `select_menu`와 `select_items` 흐름을 함께 지원한다. 여러 메뉴나 수량이 포함된 발화는 기존 장바구니 흐름으로 연결한다. LLM 호출 범위는 메뉴 및 추천 목록 화면의 `주문하기` 버튼으로 잡는다. 후속 단계의 음성 입력은 기존 규칙을 사용한다.

## 구현 순서

### 1. 메뉴명 매칭을 옵션 추출과 분리

- `backend/app/services/voice/cart.py`의 카탈로그 메뉴명 탐색을 재사용해 정규화된 문장에서 일치한 메뉴 ID와 위치를 구한다. 겹치는 위치에서는 가장 긴 이름을 우선해 “바닐라 아메리카노”를 한 메뉴로 잡는다. 서로 다른 위치의 메뉴명은 모두 후보에 남긴다.
- 명시적 주문에서 후보 하나와 수량 하나가 확인되면 기존 `select_menu`로 연결한다. 여러 메뉴나 복수 수량은 `select_items`에 연결한다. 추천 목록에서 주문하는 경우에는 기존 후보 범위를 적용한다.
- “아메리카노 말고 라떼”는 제외된 아메리카노를 담지 않는다. “아메리카노나 라떼”처럼 어느 메뉴를 원하는지 불명확하면 재입력 또는 터치 선택을 안내한다. 판매 중지된 메뉴는 유사 이름의 다른 메뉴로 대체하지 않는다.

### 2. 주문 전용 LLM 파서 추가

- `backend/app/routers/voice.py`에서 STT가 비어 있지 않고 `intent=order`이면 주문 파서를 한 번 호출한다. 메뉴명 매칭에 성공한 경우에도 호출해 규칙에 없는 표현을 해석한다. 추천 경로와 주문 파서의 프롬프트·응답 스키마는 분리하고, 기존 Responses API 전송 코드를 공유한다.
- 전사 텍스트와 현재 카탈로그의 메뉴 ID·이름·판매 여부·온도·옵션 목록 및 규칙으로 찾은 후보를 전달한다. 출력은 주문 품목별 메뉴 ID, 수량, 온도, 추가 옵션 ID와 주문 단위 이용 방식, 확인이 필요한 항목으로 제한한다. 미언급과 명시적인 “옵션 없이”를 구분한다.
- 프롬프트와 검증 사례에 “뜨듯한 아메리카노” → 아메리카노 + `HOT`을 넣는다. 메뉴가 하나로 확정되면 옵션 표현이 낯설다는 이유로 메뉴를 바꾸거나 버리지 않는다. 메뉴명이 정확히 일치하지 않을 때도 발화에서 카탈로그 메뉴가 명확히 특정되는 경우에만 모델의 선택을 사용한다.
- 호출 제한 시간을 두고 타임아웃, 키 누락, 모델 거부, 파싱 실패 시 기존 규칙으로 이어간다. 규칙으로 메뉴가 하나로 특정되면 선택을 유지하고, 여러 메뉴나 수량은 규칙으로 명확히 해석되는 경우 기존 장바구니로 넘긴다. 모호한 주문은 재입력을 안내한다.

### 3. 카탈로그 검증과 화면 연결

- 모델 응답의 구조를 검사한 뒤 메뉴 ID, 판매 여부, 수량 및 장바구니 한도, 해당 메뉴의 온도와 옵션을 서버에서 확인한다. 중복 옵션과 그룹별 선택 한도도 검증한다. 온도가 정해져야 검증할 수 있는 옵션은 보류하고, 충돌하거나 지원하지 않는 값은 확인 대상으로 표시한다.
- 단일 품목은 `select_menu`와 `recognized_options`로 기존 메뉴 확인 화면에 전달한다. 복수 품목이나 복수 수량은 `select_items`로 전달하고, 장바구니 대기열에서 품목별 온도·옵션·수량과 주문 단위 매장·포장 선택이 보존되도록 필요한 필드와 상태만 확장한다.
- 미확정 값은 기존 온도·옵션·이용 방식 화면에서 입력받는다. 화면 단계 생략은 기존 조건을 따르고, 주문 접수는 사용자의 최종 확인 후 기존 주문 API로 처리한다.

## 검증 및 완료 기준

- 메뉴 매칭 테스트에서 “뜨듯한 아메리카노”, “뜨듯한 바닐라 아메리카노”, “아메리카노 말고 라떼”, “아메리카노나 라떼”, 판매 중지 메뉴를 검증한다.
- 주문 라우터 테스트에서 STT와 LLM을 대체해 정확한 메뉴명이 있어도 주문 LLM을 한 번 호출하는지, “뜨듯한 아메리카노”가 `select_menu`와 `HOT`을 반환하는지, 타임아웃에도 아메리카노 선택이 유지되는지 확인한다.
- 잘못된 메뉴 ID·온도·옵션과 모호한 온도가 자동 확정되지 않는지 확인한다. “뜨듯한 아메리카노 두 잔이랑 아이스 라떼 한 잔, 포장”에서 품목별 온도와 수량, 주문 단위 포장이 최종 확인 화면까지 전달되는지 검증한다.
- 기존 추천·터치 주문 및 음성 장바구니 테스트를 실행한다. 마지막으로 실제 마이크와 연결된 모델로 “뜨듯한 아메리카노”를 발화해 전사 결과, 메뉴 확인, `HOT` 반영을 확인한다.

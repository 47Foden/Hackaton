# 여러 메뉴와 수량 주문

브랜치: feat/multi-item-voice-cart

- 주문 확인에서 각 메뉴 수량을 1~99잔으로 변경한다. 옵션 포함 단가 × 수량으로 계산한다.
- 계속 주문하기는 기존 목록을 보존하고 메뉴판으로 돌아간다. 최대 20개 주문 행을 지원한다.
- 음성에서 명시한 카탈로그 메뉴 이름을 긴 이름부터 매칭한다. 한/두/세/네/다섯/여섯 잔과 숫자 수량, 메뉴 앞의 온도, 메뉴 뒤의 카탈로그 옵션 이름을 처리한다.
- 여러 메뉴는 차례대로 온도·옵션을 선택한다. 마지막 메뉴의 옵션까지 고른 뒤 매장·포장을 한 번 선택해 전체 메뉴에 적용하고, 수량 확인 후 주문한다. 인식된 옵션은 미리 선택되며 터치로 수정 가능하다.
- 추천 발화는 주문 목록으로 자동 전환하지 않는다. 메뉴 별칭, 생략, 모호한 옵션 표현은 아직 모두 지원하지 않는다. 전사 결과와 최종 목록을 확인해야 한다.
- 서버가 각 메뉴 가격과 옵션을 검증해 전체 목록을 한 트랜잭션으로 저장한다. 응답 items가 개별 메뉴·수량·옵션·금액의 기준이다. 기존 최상위 필드는 호환용 대표 메뉴 및 주문 합계이며 quantity=1은 주문 묶음이다.
- 전송 이후에는 목록 편집을 잠가 같은 request_id로 재시도할 때 주문 내용이 바뀌지 않게 한다.

## 적용

기존 DB 볼륨을 삭제하지 말고 새 마이그레이션을 적용한다.

```powershell
git fetch origin
git switch --track origin/feat/multi-item-voice-cart
docker compose up -d --build backend frontend
docker compose exec backend python -m app.db.migrate
```

## 검증

frontend build, 단위 테스트, Chromium 주문 흐름 테스트 및 PostgreSQL 17 일괄 저장/재시도/롤백 테스트를 사용한다. 실제 마이크·RunPod 전사 품질과 유료 LLM 호출 성능은 이 변경의 자동 테스트 대상이 아니다.
